## 引言

在KityMinder脑图编辑器中，命令系统是实现用户交互功能的核心机制。每个可执行的操作（如添加节点、设置样式、撤销等）都被封装为一个命令对象。为了提供良好的用户体验，系统需要能够动态判断每个命令在当前上下文中的可用性状态，并据此更新用户界面（如按钮禁用、高亮等）。这一功能通过`queryCommandState()`方法实现，它基于命令的上下文感知能力，返回-1、0、1三种状态值来表示命令的当前状态。

本文档将深入分析`queryCommandState()`方法的工作原理，详细解释三种状态值的含义及其在用户界面中的具体体现，阐述`Command`基类中`queryState()`方法的默认实现以及如何在具体命令中重写该方法以实现上下文感知的状态判断，并结合`Architecture.md`中`Command`抽象类的定义，说明状态查询在用户体验和功能控制中的重要作用。

## 命令状态查询机制

命令状态查询机制是KityMinder命令系统的重要组成部分，它允许系统在不实际执行命令的情况下，预先判断该命令在当前编辑器状态下的可执行性。这一机制主要通过`Minder`类的`queryCommandState()`方法和`Command`基类的`queryState()`方法协同工作来实现。

当调用`minder.queryCommandState('commandName')`时，系统首先通过`_getCommand()`方法查找对应的命令实例，然后调用`_queryCommand()`方法，该方法会尝试调用命令实例上的`queryState()`方法并返回其结果。如果命令不存在或未定义`queryState()`方法，则返回默认值0。

## 三种状态值的含义与UI体现

命令状态查询返回三种整数值：-1、0和1，它们分别代表不同的命令状态，并直接影响用户界面的呈现方式。

- **-1（不可执行）**：表示命令当前不可用。在用户界面中，对应的按钮通常会被禁用（灰色显示），用户无法点击执行。例如，当没有选中任何节点时，“删除节点”命令的状态为-1，删除按钮呈现为灰色。
- **0（可执行）**：表示命令当前可用，但尚未执行或未处于激活状态。这是大多数命令的默认状态。在用户界面中，对应的按钮为正常可点击状态。例如，“加粗”命令在有文本选区时状态为0，按钮可点击。
- **1（已执行）**：表示命令当前可用且已经执行过，通常用于表示一种“激活”或“开启”的状态。在用户界面中，对应的按钮可能会被高亮或显示为按下状态。例如，“加粗”命令在选区文本已经加粗时状态为1，按钮呈现为高亮状态。

这些状态值为用户提供了直观的视觉反馈，使用户能够清楚地了解当前可以执行哪些操作，从而提升软件的可用性和用户体验。

## Command基类中的queryState()方法

`Command`基类在`src/core/command.js`文件中定义了`queryState()`方法的默认实现。该方法非常简单，直接返回常量`COMMAND_STATE_NORMAL`（值为0），表示命令默认是可用的。

```javascript
queryState: function(km) {
    return COMMAND_STATE_NORMAL;
}
```

这种设计遵循了“约定优于配置”的原则，即大多数命令在大多数情况下都是可用的。对于需要根据上下文动态判断状态的命令，开发者可以通过继承`Command`基类并重写`queryState()`方法来实现自定义的状态判断逻辑。基类还提供了`isContentChanged()`和`isSelectionChanged()`等方法，用于标记命令执行后是否会影响内容或选区，这些信息可以被撤销系统和事件系统使用。

## 具体命令中的queryState()重写示例

在实际应用中，许多命令都需要根据当前编辑器的状态来动态判断其可用性。以下是几个重写`queryState()`方法的具体示例：

### 文本编辑命令（TextCommand）

在`src/module/text.js`中定义的`TextCommand`，其`queryState()`方法检查当前是否恰好有一个选中的节点。只有当满足此条件时，命令才可用（返回0），否则返回-1。

```javascript
queryState: function(minder) {
    return minder.getSelectedNodes().length == 1 ? 0 : -1;
}
```

### 样式复制命令（CopyStyleCommand）

在`src/module/style.js`中定义的`CopyStyleCommand`，其`queryState()`方法不仅检查是否有选中的节点，还检查该节点是否具有任何自定义样式。只有当节点存在且具有样式时，复制命令才可用。

```javascript
queryState: function(minder) {
    var nodes = minder.getSelectedNodes();
    if (nodes.length !== 1) return -1;
    return hasStyle(nodes[0]) ? 0 : -1;
}
```

### 剪切命令（CutCommand）

在`src/module/clipboard.js`中定义的`CutCommand`，其`queryState()`方法检查是否有选中的节点。如果有，则返回0，表示可以剪切。

```javascript
queryState: function(km) {
    return km.getSelectedNode() ? 0 : -1;
}
```

### 只读模式下的状态查询

在`src/core/readonly.js`中，当编辑器进入只读模式时，`queryCommandState()`方法被重写，使得所有命令（除了少数例外）的状态都返回-1，从而全局禁用所有编辑操作。

```javascript
me.queryCommandState = function(type) {
    var cmd = this._getCommand(type);
    if (cmd && cmd.enableReadOnly) {
        return me.bkqueryCommandState.apply(me, arguments);
    }
    return -1;
};
```

这些示例展示了如何通过重写`queryState()`方法，实现对“加粗”命令在文本选区和非文本选区的不同状态判断，以及“撤销”命令在历史栈为空时的状态变化等复杂逻辑。

## 状态查询在用户体验中的作用

状态查询机制在提升用户体验方面发挥着至关重要的作用。它通过提供即时、准确的视觉反馈，帮助用户理解当前系统的状态和可用操作。

首先，它实现了**预防性错误处理**。通过禁用不可用的命令按钮，系统可以防止用户执行无效操作，从而避免产生错误或意外结果。例如，当没有选中节点时禁用“删除”按钮，可以防止用户误操作导致数据丢失。

其次，它增强了**界面的可发现性**。用户可以通过观察按钮的启用/禁用状态，快速了解在当前上下文中可以执行哪些操作，而无需记忆复杂的操作规则。

最后，它支持**状态感知的交互**。例如，“加粗”按钮的高亮状态直观地反映了当前选区文本的格式，使用户能够一目了然地了解文档的格式状态。

## 状态查询与执行权限控制的关联机制

状态查询与命令执行权限控制之间存在着紧密的关联。`execCommand()`方法在执行命令前，会先调用`queryCommandState()`进行状态检查。如果返回值为-1（或非正数），则直接中断执行，返回`false`。

```javascript
if (!cmd || !~this.queryCommandState(name)) {
    return false;
}
```

这种机制确保了只有在命令状态为0或1时，命令才能被成功执行。这不仅是一种安全检查，也是一种权限控制手段。例如，在只读模式下，通过全局修改`queryCommandState()`的返回值，可以有效地阻止所有编辑命令的执行，从而实现对编辑权限的控制。

此外，状态查询的结果还可以被用于更复杂的权限管理策略，例如基于用户角色或文档状态的细粒度权限控制。

## 结论

命令状态查询是KityMinder命令系统的核心功能之一，它通过`queryCommandState()`和`queryState()`方法，实现了对命令可用性的动态判断。三种状态值-1、0、1分别代表不可执行、可执行和已执行，这些状态在用户界面中通过按钮的禁用、正常和高亮状态得到直观体现。

`Command`基类提供了`queryState()`的默认实现，返回0表示命令默认可用。具体命令通过重写该方法，可以根据当前编辑器状态（如选区、内容、模式等）实现上下文感知的状态判断。这种机制不仅提升了用户体验，防止了无效操作，还与命令执行权限控制紧密关联，确保了系统的安全性和稳定性。

通过深入理解这一机制，开发者可以更好地设计和实现功能丰富、用户友好的交互式应用。
